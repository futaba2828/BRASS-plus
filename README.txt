BRASS+ 修正版 — メールログイン・アカウント削除・パスワード表示・同期修正

主な変更
- ユーザー名欄をなくし、メールアドレス＋BRASS+専用パスワードで登録／ログイン
- パスワード入力欄に目のマーク（表示／非表示）を追加
- アカウント完全削除（本人確認あり）。共有グループそのものや他メンバーのデータは削除しない
- パスワード再設定メールをResend APIまたはSMTPで送信。送信サービスが受け付けた場合だけ画面に「✓ 再設定メールを送信しました」と表示
- アカウント同期時に、そのアカウントの参加グループ一覧と現在のグループを優先し、前のアカウントのグループが残る問題を軽減
- 同じイベントIDの通知を重複表示しないように修正

更新方法
1. ZIPを展開し、brass_supabase_bundle内の index.html と server.js をGitHubリポジトリの同名ファイルに上書きしてコミットしてください。package.jsonも同梱していますが、依存関係を変更していないため通常は更新不要です。
2. GitHub Pagesの反映を待ち、RenderがLiveになることを確認してください。Renderのデプロイ元に同じserver.jsが反映される必要があります。
3. Supabaseのデータを削除したり、テーブルを作り直したりしないでください。既存データを保持したまま使う想定です。

パスワード再設定メールの設定（Render → Environment）
【Resendを使う場合】
- RESEND_API_KEY = Resendで発行したAPIキー
- RESEND_FROM = 認証済みドメインの送信元（例：BRASS+ <noreply@自分の認証済みドメイン>）
- BRASS_PUBLIC_URL = https://futaba2828.github.io/BRASS-plus/

RESEND_FROMを設定しない場合はテスト用送信元 onboarding@resend.dev を使います。ただしResendのテスト送信元は送信先に制限があるため、一般ユーザーのGmailへ送るにはResend側で独自ドメインを認証し、そのドメインのアドレスをRESEND_FROMに設定してください。送信先の制限やドメイン未認証はコードから回避できません。

【SMTPを使う場合】
RESEND_API_KEYを設定しないで、SMTP_HOST、SMTP_PORT（通常587）、SMTP_SECURE（通常false）、SMTP_USER、SMTP_PASS、SMTP_FROM、BRASS_PUBLIC_URLを設定してください。

設定を変更したらRenderで再デプロイしてください。送信失敗時は画面にエラーが出て、Renderのログにも原因が記録されます。パスワード再設定リンクは30分で期限切れになります。

注意
- パスワード再設定の「送信しました」は、メールサービスが送信リクエストを受け付けた時点の表示で、受信トレイへの到達を保証するものではありません。迷惑メールも確認してください。
- アカウント削除は取り消せません。削除前に本人確認パスワードを入力し、確認ダイアログで承認する必要があります。共有グループ自体は削除しません。
- 本番データに対する実地テストはこの環境から実行できていません。既存データやSQL設定を変更せず、更新後にログイン・グループ切替・メール送信を確認してください。
